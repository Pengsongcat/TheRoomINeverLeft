# GlitchBlur — 独立的左右颜色拖影

将物体放到 `GlitchBlur` Layer。`Spatial Ghosts` 的副本会继承这一层，因此也会经过该效果。

在 `Assets/Settings/VR_Renderer.asset` 的 `GlitchBlur (Horizontal Smear)` Renderer Feature 中调整：

- 横向拖影长度：主体轮廓内及附近使用的横向采样半径，默认 100，相机渲染像素单位。与物体世界坐标缩放不同。
- 纵向柔化：默认 2 像素，仅轻微柔化上下边界，避免变成均匀雾团。
- 原像保留：主体轮廓内及附近的原像混合权重，默认 0.85；越高主体越明确。
- **外围拖影长度**：新增，默认 150。向左右远离源物体轮廓后，渐变到这个采样半径。
- **外围原像保留**：新增，默认 0.05。外围与未拖影影像的混合权重；外围通常没有原像，因此调高会收淡远端拖影，调低会保留更多远端色带。
- 横向色带错位：默认 0.08；0 为纯水平拖影，越大不同行之间越错开。
- 色带数量：默认 40。
- 色带变化速度：默认 0，画面静止。调高后色带缓慢移动。
- 降采样倍率：默认 2。较高值降低开销，但细节更软。
- Opacity：整体效果不透明度。

近 / 远分区依据每条水平扫描线上距可见源轮廓的像素距离，不依据整个屏幕中心，也不是世界空间距离。轮廓内使用主体设置；轮廓外在两个长度最大值的一半范围内平滑过渡，再使用外围设置。实现为两种长度的拖影结果渐变混合，保持主体附近独立。两组长度与两组权重分别设为相同值可恢复原来的均匀效果。Layer 中若有多个物体或几何残影，其可见轮廓都会作为源，不单独识别某一个中心物体。

这是独立的 C# Renderer Feature + HLSL 图像处理 Shader，不会修改 SpatialGhost 的材质 Shader Graph 或 ScreenBlur 的 Shader/参数。效果只采样该层影像，不拉伸整个背景。按屏幕水平展开，三维位置仍由源模型及 Spatial Ghosts 决定。

已接入 VR_Renderer。普通 Opaque/Transparent Layer Mask 均排除 GlitchBlur，防止清晰原像被重复绘制；Camera Culling Mask 必须包含 GlitchBlur。其他 Renderer Data 需另行添加本 Feature 并设置同样的过滤规则。

支持不透明和常规 Alpha 透明材质，保留预乘 Alpha 和深度遮挡检查。透明层只使用代表性前表面深度，交叠透明物体、不同特效层之间的遮挡不是逐层精确解。

左右眼纹理布局沿用相机描述；每眼独立采样。头显双眼观感、Android 构建和 GPU 性能仍需目标设备验证。大拖影长度会增加采样成本。

当前调试配置：内圈长度 18、原像保留 0.85；外圈长度 63、原像保留 0.05。内圈少受影响，外圈更长、更散。原像保留与拖影强度方向相反。

## MeshFog 兼容
MeshFogVolume 现在使用插值的投影屏幕坐标，支持 GlitchBlur 降采样；离屏深度写入首个有效雾采样点，空体积像素丢弃，避免包围盒背面造成错误遮挡。普通雾仍不写相机深度。请给实际显示的 FogVolume 设置 GlitchBlur Layer，而不只是父物体。
验证：选择雾或其父物体，运行 Tools > TRINL > Validate GlitchBlur Fog。检查普通/1x/4x渲染、拖影、完全和部分遮挡、正交及透视相机；报告保存在 Library/GlitchFogValidation。头显与 Android 尚未验证。
