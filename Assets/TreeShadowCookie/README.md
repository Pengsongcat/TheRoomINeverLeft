# TreeShadowCookie — 程序化树影（木漏れ日）

实时生成一张树影贴图，URP 灯光 Cookie 和 VLB 的 Volumetric Cookie HD 都能直接用。
可以用脚本或 Timeline 控制起风、太阳光强度、模糊度、晕散度、树叶数量。

在任意物体上 Add Component → TRINL → Tree Shadow Cookie。两种接法：

- 把灯拖进「灯光 Cookie」、把带 `VolumetricCookieHD` 的光束拖进「VLB 体积 Cookie」：
  启用时自动换上本贴图，**停用组件时还原成原来的 Cookie**，方便和视频版对比
- 或者在「输出到 RenderTexture」里指定 `TreeShadowCookieRT`，再把这个 RT 直接拖到任何 Cookie 字段上。
  组件要保持启用，否则贴图停在最后一帧

## 结构

贴图由两部分相乘：

**远景树冠（圆形光斑）**，在 shader 里生成。真实的树影光斑是圆的、大小相近，和叶隙的形状无关：
每个小叶隙都是一个小孔，在墙上成像出的是太阳的像。所以墙上的光 = 树冠透光图 × 太阳圆盘的卷积，
「光斑模糊度」是均匀圆盘的半径，不是高斯模糊。树冠几乎是封闭的，叶隙只出现在"薄冠"区域，
所以光斑稀疏成簇，团与团之间是暗部。

**树（树枝与树叶）**，在 CPU 上生成并逐帧摆姿势，画成几何体：

- 主枝从画面边缘伸进来，逐级分出侧枝和细枝（共 4 级），叶子带叶柄长在细枝上，偏向枝梢
- **风是按层级传递的**：每根枝从父枝当前的位置长出来，所以主枝晃时整簇跟着动；
  细枝摆得比粗枝多、更快；叶子在细枝上再抖动和侧转
- **远近模糊**：影子的半影随离墙距离变大。每根主枝有自己的远近，侧枝在此基础上浮动。
  树被分成近 / 中 / 远三个深度带，各自用自己的太阳圆盘模糊；落在两带之间的枝叶按比例分到两边，
  所以模糊是渐变的而不是跳档
- 叶形：枫叶（5 片尖裂片按真实角度排：顶裂片朝上、侧裂片约 48°、下裂片短且朝两侧）/ 卵形叶 / 混合

## 参数

**阳光**：太阳光强度、阴影亮度（默认 0.06，对齐场景里原视频 cookie 的阴影）、对比度、
光斑模糊度（远景）、近处树枝模糊、远处树枝模糊（中间的树枝在两者之间渐变）、晕散度 / 范围、边缘圆形衰减。

**树枝与树叶**

| 参数 | 含义 |
|---|---|
| 树叶数量 | 0～4000，长在细枝上的叶子总数 |
| 叶形 | Maple / Ovate / Mixed |
| 叶片大小 | |
| 主枝数量 | 0～5。0 = 不画树，只保留远景光斑 |
| 枝条粗细 | |
| 树的方向 | 主枝伸进画面的方向，0 = 从左往右，90 = 从下往上 |
| 树离墙的距离 | 0 = 整棵树贴墙（清晰），1 = 很远（很糊） |
| 远近分布 | 各根树枝远近的差异，0 = 一样远 |

**风**：风力（目标）、过渡时间、摇摆速度、风向、阵风、枝条摆动、叶片翻转、以及：

| 参数 | 含义 |
|---|---|
| 顺风倾斜 | 起风时整棵树被吹向下风方向，细枝弯得最多 |
| 风中模糊扰动 | 每片区域在清晰和模糊之间以各自节奏起伏（风速 1 时约 0.35 Hz，相邻区域错开），阵风经过处更强 |
| 风中拖影 | 影子沿风向轻微拖长 |

**远景树冠**：随机种子（同时决定树的形态）、远景叶片尺寸、远景树冠密度（默认 0.2）、疏密变化。

## 脚本控制

```csharp
using TRINL.Rendering;

public TreeShadowCookie tree;

tree.StartWind(1f, 3f);      // 3 秒内起风
tree.StopWind(2f);           // 2 秒内停风
tree.SetWind(0.4f, 1f);      // 1 秒内过渡到 0.4
tree.SnapWind();             // 跳过过渡

tree.leafCount = 1200;       // 结构参数改了会自动重建树，Timeline 驱动也一样
tree.sunIntensity = 1.5f;
tree.branchBlur = 0.05f;

float w = tree.CurrentWind;
RenderTexture t = tree.Output;
tree.Advance(dt);            // 手动推进时间，比如 Time.timeScale = 0 时
```

## 实现要点

- 树的几何在 `TreeShadowCookie.cs`：生成（种子决定）→ 每次渲染做正向运动学 → 只更新顶点位置，
  拓扑、UV、深度带权重在重建时算一次。结构参数的哈希变化时自动重建。
- 树画进一张白底 RGBA 贴图，`Blend DstColor Zero` 相乘，R/G/B 三个通道就是近 / 中 / 远三个深度带的透光。
- 每个模糊都是同一个圆盘 pass，降采样到半径约 7 个像素。**降采样级别和采样点数只看基础半径，
  不随风变化**：风力渐变时切换级别会让画面跳一下，采样点数一变所有采样位置也会重排。
  采样点数留了 3 倍余量来应对风中的放大和拉长。
- 晕散从所有层相乘后的结果里取亮斑。
- URP 的 cookie atlas 只在 RenderTexture 的 `updateCount` 变化时重新拷贝，每次渲染后都会调用 `IncrementUpdateCount()`。

## 已验证

桌面编辑器，512×512：

- Shader（8 个 pass）与 C# 编译通过，控制台无错误无警告。
- 方向：「树的方向」= 90° 时主干从画面下方伸入。
- 默认值亮部占 44%、均值 0.502，与参考照片（约 45%）接近；
  远景密度 0.15～0.3、树叶 400～700 时亮部在 30%～56% 之间。
- 起风不改变曝光：无风均值 0.502，满风（2 秒内 6 帧平均）0.503。
- 风力 0→1 渐变 1 秒：逐帧变化平均 0.0020、最大 0.0030，没有跳变。
- 模糊扰动：把树的摆动全部冻住只留风，1 秒内画面变化量 0.0151（扰动关）→ 0.0915（扰动 1）。

## 和已有视频 cookie 的关系

`VideoLightCookieURP.Start()` 会把灯光 cookie 设回视频 RT，本组件每次渲染前会检查并重新接管。
视频本身仍在解码（`TreeHDShadowVideoRT` 4080×4080，约 66 MB 显存），确定改用程序化版本后，
建议停用 `BeamLeafSHadowHD` 上的 VideoPlayer 和 `VideoLightCookieURP`。

## 限制

- **头显 GPU / CPU 开销未实测。** GPU 上最重的是远景树冠 pass（每像素约 36 次叶片求值）和最多 96 点的圆盘采样；
  CPU 上每次更新要摆约 400 根枝、数百到数千片叶子，并上传顶点。Quest 上建议先用 256 分辨率、树叶数量控制在 1000 以内。
- 没有真的进 Play 模式测试。
- 深度带是三档近似：介于两带之间的枝叶被拆成两份分别模糊，核心处不会完全不透光。
- 远景树冠的叶子和树上的叶子是两套东西：远景仍是椭圆叶，因为它会被模糊成光斑，看不出叶形。
- 导出 PNG 查看时注意：Alpha 通道也存了同一个值，查看器会按半透明显示，阴影会发白、出现"暗环"。这是显示问题。
- 时间在 4096 秒处回绕以保持 sin() 精度，风速 1 时约每 68 分钟有一次图案跳变。
